# Tools

- **MCP first.** Work through the ordered tool list your prompt gives you (the routing line for your layer and jurisdictions). Primary law comes from the legal MCP servers named there; a general web result is never the citation.
- **EU law goes through CELEX.** `legalviz_search_eu_law` or `legalviz_resolve` turns a title, citation or EUR-Lex URL into a CELEX id; `legalviz_get_law_part` with `part="structure"` gives the table of contents and a second call the pinpointed article or recital (`version` for a point-in-time reading). Take slices, not whole acts, and name the tool that returned the text when you register the source. `version="current"` answers with the consolidated CELEX it read, in `versionCelex`, and `legalviz_get_law_relations` lists the amendments behind it — that pair, not memory, says which text is in force. The AI Act, for instance, currently reads as `02024R1689-20260727`, amended by Regulation (EU) 2026/1744 (Digital Omnibus on AI, CELEX `32026R1744`).
- **A CJEU judgment is cited at its CELEX address.** The CELEX of a judgment is `6<year>CJ<number>`, so C-252/21 is `62021CJ0252`, and it is served on two hosts: `https://publications.europa.eu/resource/celex/62021CJ0252` fetched with `Accept: application/xhtml+xml` (this one also holds the older judgments and stays up while EUR-Lex is in a challenge window) and `https://eur-lex.europa.eu/legal-content/EN/TXT/?uri=CELEX:62021CJ0252`. `curia.europa.eu` is not a source at all: every path there — `liste.jsf`, `celex.jsf`, `document.jsf`, `showPdf.jsf` — answers with the same JavaScript shell for every case number, so a curia URL is not registered and not cited, in `--url` or anywhere else.
- **EUR-Lex and Cellar.** An EUR-Lex answer of HTTP 202 with `x-amzn-waf-action: challenge` is a bot challenge: retrying will not clear it, so go to Cellar (`publications.europa.eu/resource/celex/<CELEX>`, `Accept: application/xhtml+xml`, `Accept-Language: eng`) or back to LegalViz. Without that `Accept` header Cellar answers with tens of megabytes of RDF, and pinpoint anchors `id="art_N"` exist only on the consolidated CELEX `0YYYYRNNNN-YYYYMMDD`.
- **UK law comes in slices too.** `uklegal_legislation_search` → `uklegal_legislation_get_toc` → `uklegal_legislation_get_section` for a statute (the section answer carries extent and in-force metadata), and `uklegal_case_law_search` → `uklegal_judgment_get_header` → `uklegal_judgment_get_index` → `uklegal_judgment_get_paragraph` for a judgment. `uklegal_case_law_search` ranks poorly on party names — it can return ten results with none of them the case you named — so search by subject matter and confirm the hit through `uklegal_judgment_get_header` before you rely on it; `uklegal_citations_resolve` says whether a citation points at a real document and `uklegal_citations_format_oscola` gives its OSCOLA form. `lex_get_explanatory_note_by_section` is the explanatory-note source for a section and `lex_search_amendments` the amendments that changed it.
- **France and Switzerland have their own bundled servers.** `justicelibre_get_law_article` takes `code` (a short abbreviation such as `CT` for the Code du travail) and `num` (the article, e.g. `L1121-1`) — a wrong `code` makes the server list all 79 it knows — and `justicelibre_resolve_law_number` finds a law or decree outside the codes; `justicelibre_search_judiciaire` / `search_conseil_etat` / `search_cc` cover the three French orders and `justicelibre_search_cnil` / `search_doctrine` the regulator and the commentary. `opencaselaw_get_law(sr_number, article)` returns a Swiss provision with its consolidation date and the consolidations already scheduled, `opencaselaw_search_decisions` / `get_decision` / `get_regeste` / `find_leading_cases` the case law, `opencaselaw_get_doctrine` / `search_commentaries` the literature. Both answer with a `source_url` on the official portal (Légifrance, Fedlex) — that URL is what you register, never the MCP endpoint.
- **US federal regulations come from `fedregs_*`.** `fedregs_regulations_get_cfr_section` takes `title`, `part` and `section` (16, "312", "312.3") and returns the codified text as of a date — cite it as `16 CFR 312.3` at `https://www.ecfr.gov/current/title-16/section-312.3`; `fedregs_regulations_browse_cfr` walks a title or part; `fedregs_regulations_search_rules` and `fedregs_regulations_get_document` are the Federal Register (cite `https://www.federalregister.gov/d/<FR number>`). The U.S. Code stays on govinfo.gov. Never WebFetch ecfr.gov or federalregister.gov pages: they answer a stub; the APIs go through `mf sources fetch`.
- **`ldh_search` is not a search tool.** Legal Data Hunter is a resolver: `ldh_resolve_reference` with an exact citation returns the right provision, while `ldh_search` on the same question returns hits at the noise floor. Use it only when you already know what you are asking for by name, and never as the way to discover which provision applies.
- **A call that needs headers goes through `mf sources fetch`.** `WebFetch` sends only a URL and `curl` is not auto-allowed, so the Cellar contract (`Accept: application/xhtml+xml`, `Accept-Language: eng`), the BOE block endpoint (`Accept: application/xml`), the NL `_manifest.xml` and the RIS OGD JSON are fetched with `mf sources fetch --workdir <W> --url <U> [--accept <mime>] [--lang <code>] [--out <path under research/raw/>]`: it sends the plugin's headers, refuses any host outside `hooks/allowlist.txt`, saves the body and answers `{status, code, content_type, bytes, sha256, path, interstitial}` — register the file with `--tool "mf-fetch <host>"`, and never quote or register a body whose `status` is `unchecked`.
- **Fail-soft portals.** If an MCP call fails or returns nothing usable, fetch the issuing body's own portal from that same list. If that also fails, record the gap in your output ("primary source unreachable, manual research required") and move on. Never fill a gap from memory.
- **Rate limits.** On an explicit rate-limit answer (429, "quota", "throttle", "too many requests"), wait the server's `Retry-After` — capped at 60 seconds, and a longer value means do not wait at all — then retry once. If the retry fails too, stop calling that server for the rest of the run, continue on the fail-soft path, and log it once:

  `${mf} events log --workdir "${work_dir}" --event mcp_ratelimit_fallback --actor <agent_type> --data '{"server":"…","retry_after":…}'`

  A single timeout is not a rate limit; retry that normally.
- **A human challenge is the user's to answer.** If a portal answers with a CAPTCHA or an interstitial meant for a person, never try to solve or work around it: say which page it is and ask the user to open it in their own browser and paste the passage back.
- **WebSearch.** Follow the layer row in your prompt — it says whether search may be a primary tool for you or discovery only. Discovery only means search may locate a URL; the text you rely on and the citation you record come from the authoritative source.
- **Your declared input is read-only.** The files your prompt names as the step's input are read-only for you — a step whose declared input changes while it runs is rejected, so leave `mf sources verify`, `mf sources liveness` and `mf sources register` to the pipeline.
- **Call budget.** Your share of the run's MCP budget is stated in your prompt. Spend it on the key instruments for each issue rather than on exhaustive coverage, and when it is gone, say so in your output instead of continuing.
