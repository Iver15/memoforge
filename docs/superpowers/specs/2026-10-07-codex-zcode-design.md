# Memoforge для Codex и ZCode

Дата: 7 октября 2026 года. Статус: спецификация для согласования.

## Цель и согласованный подход

Пользователь хочет отдельные устанавливаемые версии Memoforge для Codex и
ZCode, с документацией и взаимодействием на русском языке. Согласованный
подход: одно Python-ядро и отдельные пакеты для каждой платформы.

Под ZCode понимается приложение Z.ai: на этом Mac установлено
`/Applications/ZCode.app`, версия 3.14.4. Проверенная версия Codex CLI — 0.157.1.
Основная среда приёмки — этот Mac; наличие Windows-обёртки в пакете само по
себе не означает проверку работы в Windows.

Каждая сборка должна позволять начать юридический меморандум, ответить на
вопросы, согласовать план, продолжить прерванную задачу, проверить источники
и получить итоговый DOCX. Отдельная установка означает собственное имя
плагина, настройки и инструкции; общее ядро получает исправления один раз.

## Рассмотренные варианты

1. **Общее ядро и два адаптера — выбранный вариант.** Отличия инструментов
   и установки сосредоточены в адаптерах. Сборщик включает нужные общие файлы
   в каждый самостоятельный пакет.
2. **Два независимых форка.** Проще начать копированием, но версии анализа,
   проверок и экспорта будут расходиться. Этот вариант не выбран.
3. **Один универсальный плагин для всех сред.** Меньше пакетов, но условные
   инструкции затруднят запуск и не дадут пользователю отдельных версий.
   Этот вариант не выбран.

## Состояние исходного проекта

Memoforge 2.0.0 — плагин Claude Code/Cowork. Python-машина состояний и
экспорт DOCX находятся в `scripts/memoforge`; вход — `scripts/mf` или
`scripts/mf.cmd`. Пять пользовательских сценариев представлены навыками
`memo`, `continue`, `status`, `style` и `brief`.

Основные зависимости от Claude: `CLAUDE_PLUGIN_*`, пути `.claude/plugin-data`,
модели `opus`/`fable`/`sonnet`, квалифицированные типы `memoforge:<agent>`,
инструменты `Agent` и `AskUserQuestion`, необязательный Cowork Artifact.
Версия ядра сейчас читается из `.claude-plugin/plugin.json`.

Русский README и актуальная документация уже переведены. Эти изменения и
исправления переносимости тестов сохраняются. Базовая проверка выполнена:
3646 тестов, 10 разрешённых платформенных пропусков; пробный прогон машины
состояний завершён без нарушений инвариантов. Это проверка ядра, а не новых
адаптеров и не полноценного исследования с внешними юридическими сервисами.

## Структура пакетов

Исходники адаптеров размещаются в `platforms/codex/` и `platforms/zcode/`.
Сборщик создаёт в игнорируемом `dist/` два самостоятельных каталога и ZIP:
`memoforge-codex` и `memoforge-zcode`. Каждый пакет содержит собственный
манифест, пять сценариев, необходимые инструкции ролей, настройки MCP,
Python-ядро, схемы, шаблоны, зависимости, лицензию и русский README.

Сборщик копирует общий runtime из исходного дерева. Вручную поддерживаемых
копий ядра в `platforms/` нет. Преобразования ограничены явно перечисленными
файлами адаптера; массовая замена названий инструментов в юридических
инструкциях не используется. Все ссылки пакета остаются внутри его каталога.
ZIP сохраняет исполняемость POSIX-обёртки.

Пакет Codex использует поддерживаемый формат `.codex-plugin/plugin.json`,
`skills/` и `.mcp.json`. Пакет ZCode использует `.zcode-plugin/plugin.json`,
`skills/`, `agents/`, команды входа и `.mcp.json`. Локальные записи marketplace
подготавливаются отдельно для каждого хоста.

## Профиль выполнения и настройки

Общий runtime получает явный профиль `claude`, `codex` или `zcode`.
Исходный пакет без указания профиля сохраняет поведение Claude. Новые пакеты
задают профиль в собственной обёртке. Неизвестный профиль — понятная ошибка,
а не автоматическое переключение на другую платформу.

Профиль определяет путь к данным, значения по умолчанию и описание способа
запуска роли. Обёртки POSIX/Windows и Python должны выбирать одинаковый
каталог данных. Приоритет имеет корректный каталог, предоставленный хостом;
резервные каталоги новых сборок — `~/.codex/plugin-data/memoforge-codex` и
`~/.zcode/plugin-data/memoforge-zcode`, затем `.data` внутри своего пакета.
Для Windows используются соответствующие каталоги в `%LOCALAPPDATA%`.

Новые сборки по умолчанию используют `memo_language=ru`, `ui_language=ru` и
`dashboard=false`. Явные пользовательские настройки имеют приоритет.
Модель наследуется от текущей среды; имена моделей Claude не передаются
Codex или ZCode. Исходный профиль Claude сохраняет свои модели и настройки.

Профиль сохраняется в новой задаче. Старые задачи без профиля считаются
задачами Claude. Первоначальная версия не обещает перенос незавершённой
задачи между платформами: несовместимое продолжение отклоняется с объяснением.
Файлы настроек, launcher cache и указатель последней задачи разных пакетов
не должны обращаться к резервному каталогу Claude.

Самостоятельный пакет должен сообщать правильную версию без манифеста
Claude. При реализации синхронизируются версия ядра, манифесты и сведения
сборки, чтобы обновление уже установленного плагина обнаруживалось хостом.

## Запуск агентов и протокол

Сохраняется цикл `mf next → действие → mf report`. Только CLI меняет
каноническое состояние задачи. Агенты пишут в выданные промежуточные пути;
успешный ответ публикуется после проверки схемы. Порядок фаз, заморозка
источников, точные цитаты и правила повторов остаются общими.

Для Codex роль запускается доступным инструментом создания подагента.
Её задача включает общие системные правила роли и динамическое задание
из dispatch-плана; копировать только динамическое задание недостаточно.
Модель наследуется от хоста. Для ZCode используются собственные определения
агентов и его механизм запуска, также без обязательной модели Claude.
Адаптер явно разрешает делегирование соответствующих слотов.

Параллельные группы запускаются до ожидания результатов. Каждый слот
сообщает результат отдельно. Отсутствующий инструмент подагентов, пустой
ответ или несохранённый результат не считаются успехом; CLI получает ошибку
слота и применяет существующие правила повторов и завершения.

Команды `kind: script` выполняются с аргументами из CLI без изменения их
смысла. `inline-llm` сохраняет JSON по заданному пути с последующей проверкой.
Готовые файлы показываются пользователю абсолютными ссылками.

## Диалог, ошибки и внешние сервисы

Новые адаптеры используют текстовые подтверждения плана и источников.
Существующий механизм переключения gate-channel и `mf gate parse` сохраняет
идентификатор шага, попытку и поколение. Ответ пользователя не заменяется
догадкой адаптера. Отмена обрабатывается существующим `task cancel`.

Код ошибки или JSON с `errors` не означает выполненный шаг. Повторы,
проверка результатов и аварийное завершение остаются под контролем ядра.
Статус, продолжение, стиль и краткая записка используют те же правила.

В новые пакеты включаются исходные объявления десяти MCP-сервисов.
Маршрутизация опирается на обнаруженные пространства имён и суффиксы
инструментов. Установка не означает наличие авторизации или доступность
каждого сервиса. Недоступность явно отражается в состоянии исследования.

Claude hooks не копируются как обязательное условие запуска новых сборок.
Инициализация зависимостей выполняется при установке и проверяется при входе
в сценарий. Правила разрешений каждой среды сохраняются. Новые версии не
требуют Cowork Artifact; прогресс показывается в чате и через `status`.

## Установка и документация

Подготавливаются русские инструкции для установки из локального каталога
и для последующего распространения готового пакета. На этом Mac сборки
регистрируются в Codex и ZCode доступным штатным способом. Существующие
плагины и настройки пользователя сохраняются. Если загрузка требует новой
сессии или перезапуска приложения, это указывается явно.

Документация объясняет пять сценариев, выбор модели в хосте, каталоги задач,
подключение MCP, продолжение и границы проверки. Русский язык вывода не
означает автоматическое ограничение исследования законодательством России:
юрисдикцию задают запрос и план анализа. Расширение российских источников —
следующий самостоятельный этап адаптации под русскую аудиторию.

## Критерии приёмки

1. Получены два самостоятельных пакета с русскими README и всеми ресурсами;
   они работают вне исходного checkout, в том числе в пути с пробелами.
2. Проверены манифесты, внутренние ссылки, версия и содержимое сборок;
   в пакеты не попали личные настройки, задачи, секреты и тестовые результаты.
3. Тесты подтверждают выбор профиля, изоляцию данных, русские настройки и
   отсутствие принудительных моделей Claude в новых dispatch-планах.
4. Проверены роли, параллельные слоты, неверный/пустой результат, повтор,
   текстовый gate, устаревший ответ, отмена и восстановление задачи.
5. В каждой сборке выполнен воспроизводимый пробный прогон ядра и экспорт
   русского DOCX. Прогон с фикстурами явно отделён от настоящего анализа.
6. Проверена регистрация плагина и обнаружение сценариев в каждом хосте;
   доступные проверки настоящего запуска зафиксированы отдельно от тестов.
7. Пройдены текущие тесты ядра, проверка допустимых пропусков, линтер,
   каноническая документация, версии и проверка diff. Изменения профилей не
   нарушают существующий маршрут Claude.
