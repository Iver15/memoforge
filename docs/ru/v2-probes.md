# memoforge v2 — проверки платформы (ТЗ §11)

[Указатель](README.md) · [Оригинал](../probes/v2-probes.md). Перевод документации v2.0.0. Результаты ниже перенесены из записей автора; перевод не означает повторной проверки в текущей среде.

Эти проверки отвечают на вопросы, от которых зависит архитектура. Каждую проводят **до** фиксации соответствующего решения. `mf probe P<n>` только печатает процедуру; проверку не запускает. Она требует наблюдения человека в настоящем приложении. Записывайте исход, включая неудачу.

Между наблюдениями оставляйте **25 секунд**, чтобы приложение, объединяющее обновления интерфейса, успело их показать; методика описана в `docs/attic/v0.5.0-probe-procedure.md`.

Для каждой среды нужна отдельная строка: `CLI` — Claude Code на Windows 11, и `Cowork`.

## Процедуры

`mf probe P<n>` выводит вопрос, метод и затронутый раздел. Ниже — дополнительные детали для проверки.

### P1 — Workflow плагина

Не добавляйте `workflows/` в поставляемый репозиторий до успеха P1 (§0.4, §10). Скопируйте плагин в отдельный временный каталог: `%TEMP%\memoforge-probe\` на Windows или `$TMPDIR/memoforge-probe/` в другой среде. Создайте там `workflows/ping.js` с двумя фазами, установите эту копию как локальный плагин и выполните `/memoforge:ping` в обеих средах. Наблюдайте `/workflows` и Background tasks. После записи результата удалите временную копию.

### P2 — Запуск хуков

`hooks/probe_echo.py` добавляет строку JSON в `<plugin_data_dir>/probe-echo.log`. Он не включён в `hooks/hooks.json` и не создаётся `build_hooks.py`, поскольку не входит в таблицу §8.1. Для проверки добавьте блок в `hooks.PreToolUse` установленной копии, перезапустите приложение и вызовите любой `Read`:

```json
{
  "matcher": "^Read$",
  "hooks": [
    {"type": "command", "command": "python", "args": ["${CLAUDE_PLUGIN_ROOT}/hooks/probe_echo.py", "--variant", "python"]},
    {"type": "command", "command": "python3", "args": ["${CLAUDE_PLUGIN_ROOT}/hooks/probe_echo.py", "--variant", "python3"]},
    {"type": "command", "command": "py", "args": ["-3", "${CLAUDE_PLUGIN_ROOT}/hooks/probe_echo.py", "--variant", "py-3"]}
  ]
}
```

По `argv` в журнале видно, какие варианты запустились. Если `env.CLAUDE_PLUGIN_ROOT` содержит буквальный `${CLAUDE_PLUGIN_ROOT}` или путь argv не существует, проверка провалена. Пока блок добавлен вручную, `python hooks/build_hooks.py --check` ожидаемо сообщает расхождение. После записи результата удалите блок.

### P3 — Страница прогресса

Включите `dashboard`, запустите меморандум и проверьте живые обновления в CLI и Cowork. Первый `mf next` содержит `dashboard.publish`: опубликуйте `lib/dashboard.html` с `capabilities: {db: {}}`, передайте URL команде `mf task dashboard --workdir W --url <URL>`. Каждый следующий ответ `next` применяйте одним вызовом `Artifact write_db` для `run/state`.

Фиксируйте сбой, если страница остаётся в ожидании данных или перестаёт обновляться при успешных `write_db`. Если инструмента нет, процесс должен продолжиться: `mf task dashboard --workdir W --unavailable "<error>"` устанавливает предупреждение, задача завершается штатно.

### P4 — Вопрос после запуска агента

Один запуск `Agent`, затем `AskUserQuestion`; после этого три параллельных запуска и `AskUserQuestion`. Проверяемый сбой — отсутствие ответа без явной ошибки.

### P5 — События агентов

По одному `events.jsonl` нельзя установить полный состав данных хука. `build_subagent()` в `hooks/progress_logger.py` сохраняет только `agent_id`, `agent_type` и при остановке `result`. Отсутствие `initial_prompt` и `last_assistant_message` в журнале характеризует формат записи, а не приложение. Нужно читать исходный stdin хука.

Как в P2, вручную добавьте в `hooks.SubagentStop` установленной копии:

```json
{
  "matcher": "^memoforge:",
  "hooks": [
    {"type": "command", "command": "python", "args": ["${CLAUDE_PLUGIN_ROOT}/hooks/probe_echo.py", "--variant", "subagent-stop"]},
    {"type": "command", "command": "python3", "args": ["${CLAUDE_PLUGIN_ROOT}/hooks/probe_echo.py", "--variant", "subagent-stop"]},
    {"type": "command", "command": "py", "args": ["-3", "${CLAUDE_PLUGIN_ROOT}/hooks/probe_echo.py", "--variant", "subagent-stop"]},
    {"type": "command", "command": "python", "args": ["-c", "import sys,pathlib;pathlib.Path(r'<abs>/probe-p5-stop.json').write_bytes(sys.stdin.buffer.read())"]}
  ]
}
```

Перезапустите приложение и запустите агент `memoforge:*`; достаточно `memoforge:probe-echo` или реального слота процесса. Прочитайте два файла:

- В `<plugin_data_dir>/probe-echo.log` последняя строка с `--variant subagent-stop` доказывает срабатывание: `hook_event_name` равен `SubagentStop`, `agent_type` начинается с `memoforge:`, `stdin_bytes` больше нуля.
- В `<abs>/probe-p5-stop.json` лежит точный stdin того же вызова. Установите, есть ли `initial_prompt` и `last_assistant_message` как ключи верхнего уровня и содержат ли они реальный текст. Одного `stdin_bytes` недостаточно.

Для начала агента используйте такой же блок в `hooks.SubagentStart`, вариант `subagent-start` и другой файл дампа. После записи результата удалите оба блока. Временное расхождение `python hooks/build_hooks.py --check` ожидаемо, как в P2.

### P6 — Вложенный запуск

Штатные агенты не могут выполнить этот вызов: у них либо отсутствует `Agent` в `tools:`, либо он указан в `disallowedTools`. В `agents/probe-echo.md` запрет есть и в метаданных, и в тексте: разрешён только заданный вызов Bash. Изменение лишь `disallowedTools` не позволит вложенный запуск. Временно измените весь файл установленной копии, предварительно сохранив его для точного восстановления:

1. Удалите `Agent` из `disallowedTools`, оставив `disallowedTools: Task, AskUserQuestion, mcp__cowork__*`.
2. Замените предложение о единственном разрешённом инструменте и шаг 3 раздела «What to do» одним вызовом `Agent(subagent_type="Explore", prompt="list the files in the plugin root")` с отчётом о результате. Сохраните формат `TOOLS:`/echo, заменив строку `BASH_CALL:` на `AGENT_CALL:`.
3. Перезапустите приложение и запустите `memoforge:probe-echo`. Дополнительная инструкция в запросе не нужна: изменённое тело уже задаёт действие.

Запишите, появился ли `Agent` в строке `TOOLS:` и начался ли вложенный запуск с возвратом результата. Затем восстановите весь исходный файл байт в байт: метаданные и тело. В рабочем составе агентов `Agent` остаётся запрещён (§4.1); проверка выясняет только возможности платформы. Тот же файл меняет вариант P9(b), поэтому P6 и P9 одновременно не выполняются.

### P7 — Защита Stop

Включите `stop_guard` в настройках плагина, прервите запуск в рабочей фазе вне согласования и попробуйте вернуться в процесс.

### P8 — Вывод чата

Выведите три текстовые строки, чередуя их с двумя вызовами `Agent`. Запишите момент появления сообщений и наличие подписи `P<n>/<N> · <agent> · <label>` на карточке.

### P9 — Доступные инструменты

Echo-агент выводит свой список инструментов в двух вариантах:

- (a) без `tools:`, с `disallowedTools: Agent, Task, AskUserQuestion, mcp__cowork__*`;
- (b) с `tools: Read, Write, Bash, mcp__*`.

Выполните оба варианта в CLI и Cowork. Штатный `agents/probe-echo.md` соответствует (a), как три MCP-агента. Для (b) измените только его метаданные: удалите `disallowedTools:`, добавьте `tools: Read, Write, Bash, mcp__*`; запустите снова и восстановите оригинал. Второй файл агента не поставляется.

### P11 — Копирование в подключённую папку

Завершите меморандум в Cowork с подключённой папкой. `mf finalize` копирует документ, `summary.md` и `sources/` в `/mnt/user-data/outputs/memoforge/<slug>/` (D-109), а конечный `text` показывает этот путь как `Published:`.

Затем выполните шаг из `router.md`: через файловые инструменты устройства скопируйте всю папку в `<connected folder>/memoforge/<slug>/`. Подключённая папка не смонтирована в контейнере плагина; инструменты устройства видят её как `$HOME/mnt/<folder>`.

Запишите три результата: есть ли файловые инструменты в этой сессии, дошла ли копия и видит ли пользователь файлы на своём компьютере без боковой панели результатов. CLI — контрольная среда: инструментов устройства там нет, шаг должен только напечатать пути. Попытка копировать в таком запуске CLI означает провал проверки.
